# DAON CRM

직업학교(아카데미) 운영을 위한 B2B CRM. 리드 관리부터 학생·출결·과정·CS·취업까지 한곳에서 관리합니다.

**5인 팀 프로젝트**이며, 이 저장소에는 제가 담당한 **학생 관리 · 출결 관리 · 과정/기수 관리** 3개 도메인이 담겨 있습니다.

---

## 담당 범위

세 도메인을 **데이터 모델 → 백엔드 REST API → 프론트 화면**까지 수직으로 구현하고, 팀 공용 더미 데이터와 Docker 실행 환경을 함께 세팅했습니다.

| 도메인 | 담당 내용 |
|---|---|
| 학생 관리 | 스키마 설계, 목록·필터·페이징 API, 요약 카드, 위험 학생 추출 |
| 출결 관리 | 출결 스키마, 학생×일자 그리드, 연속 결석 경고, 반별 통계 |
| 과정/기수 | 기수 스키마, 충원율·수료율 집계, 정원 임박·일정 API |
| 공통 | Flyway 마이그레이션, Faker 더미 데이터, Docker Compose |

## 기술 스택

`Java 17` `Spring Boot 4.1` `Spring Data JPA` `PostgreSQL 16` `Flyway` `Gradle` `Docker` `HTML/CSS/JS` `Chart.js` `Python(Faker)`

## 실행

```bash
cp .env.example .env     # DB 접속 정보 입력
docker compose up
```

앱과 PostgreSQL이 함께 뜹니다. DB 헬스체크가 통과한 뒤에 앱이 시작하고, 볼륨을 사용해 재시작해도 데이터가 유지됩니다. Flyway가 스키마와 시드 데이터를 자동으로 적용합니다.

## 데이터 모델

스키마는 **Flyway 마이그레이션으로만** 변경합니다. `ddl-auto=validate`로 두어 코드와 DB가 어긋나면 기동 단계에서 잡히도록 했습니다.

### `student`
학생의 기본 정보부터 출석률·과제제출률, 상담·취업 상태까지 관리하는 테이블입니다. 조회 패턴에 맞춰 반 이름과 상태에 인덱스를 걸었습니다.

### `attendance`
`UNIQUE(student_id, attendance_date)` 제약으로 **같은 날 중복 출결이 물리적으로 불가능**하게 만들었습니다. 날짜·학생별 조회 인덱스를 추가했습니다.

### `course`
과정 카테고리와 기수, 정원, 강사, 개강·종강일, 수료율을 담습니다.

### 관계
- `student` 1 : N `attendance` — 실제 외래키
- `course` 1 : N `student` — `cohort_name = class_name` 문자열 매칭(논리적 연결)

## API

패키지는 `domain/<도메인>/` 아래에 Entity · Repository · Service · Controller · dto로 나눈 레이어드 구조입니다. Controller는 엔티티를 직접 노출하지 않고 **DTO(record)로만** 응답합니다.

### `/api/students`
| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/` | 목록 (과정·기수·상태·검색어 필터 + 페이징) |
| GET | `/summary` | 요약 카드 (전체·수강중·수료예정·위험) |
| GET | `/risk-top5` | 위험 학생 TOP 5 |
| GET | `/class-names` | 필터용 반 목록 |

### `/api/attendance`
| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/summary` | 당일 출석률·상태별 집계 |
| GET | `/grid` | 학생 × 일자 출결 그리드 |
| GET | `/streak-warnings` | 연속 결석 경고 |
| GET | `/class-top5` | 반별 출석률 TOP 5 |
| GET | `/weekly` | 주간 상태 분포 (도넛 차트) |

### `/api/courses`
| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/` | 과정별 기수 목록 (정원·현재인원·충원율) |
| GET | `/performance` | 기수별 성과 (충원율·수료율) |
| GET | `/near-full` | 정원 마감 임박 |
| GET | `/schedule` | 개강·종강 일정 |

## 핵심 로직

**이탈 위험도 자동 판정**
학생의 출석률을 설정된 임계값과 비교해 `위험 / 주의 / 관심 / 수강중`으로 자동 분류합니다. 임계값은 팀의 '설정' 기능과 연동해 운영자가 조정할 수 있도록 확장됐습니다.

**연속 결석 경고**
최근 4주 출결을 최신일부터 거꾸로 훑으며 **평일 기준** 연속 결석 일수를 셉니다. 주말·휴강은 연속성을 끊지 않도록 처리했고, 기준일 이상이면 경고 목록에 노출합니다.

**충원율·수료율 집계**
기수별 `현재인원 ÷ 정원`으로 충원율을 계산하고, 정원 임박과 종료 예정을 자동 판정합니다. 종료된 기수는 수료율까지 계산해 기수 간 성과를 비교할 수 있게 했습니다.

**'오늘' 기준일 처리**
더미 데이터의 최신 날짜를 '오늘'로 사용해, 언제 데모를 실행해도 카드와 그리드가 비어 보이지 않도록 설계했습니다. 운영 전환 시에는 실제 현재 날짜로 교체하면 됩니다.

## 더미 데이터

Python + Faker(`ko_KR`)로 **관계가 정합한** 데이터를 생성해 Flyway 시드로 주입합니다. 시드값을 고정해 재현 가능하며, 로컬·스테이징 전용입니다.

- 학생 349명 (재원 249 / 수료 100)
- 출결 3,580건 (재원생 × 최근 4주 평일)
- 기수 13개 (운영중 6 / 모집중 3 / 종료 4)

단순 랜덤이 아니라 **같은 반은 같은 강사**, `cohort_name = class_name` 매칭, **출석률이 낮은 학생일수록 결석·지각이 많도록** 상관을 부여했습니다. 그래야 위험도 판정과 연속 결석 경고가 실제로 검증되기 때문입니다. 개강 전 모집중 학생, 저출석 위험군 같은 엣지 케이스도 일부러 섞었습니다.

## 화면

Figma 시안을 기준으로 3개 페이지를 구현하고 API를 `fetch`로 연결했습니다.

- **students.html** — 요약 카드, 필터·검색, 출석률·과제제출률 진행바가 있는 테이블, 페이징, 위험 학생 TOP5
- **attendance.html** — 당일 카드, 학생×일자 출결 그리드(주말 자동 처리), 연속 결석 경고, 반별 TOP5, 주간 출석률 도넛 차트
- **courses.html** — 과정→기수 트리, 4개 탭, 기수별 성과 라인 차트, 정원 임박, 개강·종강 일정

## 트러블슈팅

**Flyway out-of-order**
시드를 큰 번호로 둔 뒤 낮은 번호 스키마를 추가하니 순서 검증에서 실패했습니다. 원인을 파악하고 재적용 규칙을 정리했습니다.

**설정 파일 충돌**
`application.yml`의 flyway 키 중복과 `.properties` 병존으로 기동이 실패했습니다. YAML 구조를 하나로 통합해 해결했습니다.

**Docker 빌드 실패**
시스템 Gradle 버전이 Spring Boot 4.1과 맞지 않았습니다. Dockerfile이 프로젝트의 **Gradle Wrapper**를 쓰도록 수정했습니다.

**compose 파일명 대소문자**
Windows에서는 동작하던 대문자 파일명이 리눅스에서 인식되지 않았습니다. 소문자로 표준화했습니다.

**데이터 정합성**
세 화면이 공유하는 강사·기수 데이터가 어긋났습니다. 더미 생성 단계에서 반별 단일 강사와 기수명 매칭으로 통일해 해결했습니다.

## 보안

- 시크릿은 `.env`로 분리하고 커밋하지 않습니다 (`.env.example`만 포함)
- `.dockerignore`로 불필요한 파일의 이미지 유입 차단
- 컨테이너는 비루트 사용자로 실행
- DB 포트는 `127.0.0.1`로 격리
